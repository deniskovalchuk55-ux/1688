# Радар товарних трендів — крок 1

Перша робоча частина: збір трендів з Google Trends і YouTube, база, API і сторінка,
де видно, що росте. Далі на цей каркас нарощуються Prom, 1688, калькулятор і алерти.

## Що вже вміє

- Тягне динаміку пошукових запитів по Україні за 90 днів
- Рахує зростання за останній тиждень проти попереднього
- Знаходить свіжі відео на YouTube і рахує швидкість набору переглядів
- Шукає суміжні запити, що різко ростуть — так ловляться нові теми, яких немає в списку
- Рахує оцінку: швидкість, обсяг попиту, довіра до сигналу
- Оновлюється сама кожні 30 хвилин
- Ховає теми, які згасли, але не видаляє їх

## Чого ще немає

Цін, товарів з 1688, конкуренції на Prom, прибутку, Telegram-алертів.
Це наступні кроки.

## Запуск

### 1. Змінні

Створи `server/.env`:

```
DATABASE_URL=postgresql://...   # з neon.tech
YOUTUBE_API_KEY=...
ANTHROPIC_API_KEY=...           # поки не використовується
TRENDS_GEO=UA
COLLECT_CRON=*/30 * * * *
PORT=3000
```

Створи `web/.env`:

```
VITE_API_URL=http://localhost:3000
```

### 2. Сервер

```bash
cd server
npm install
npm start
```

Схема бази застосується сама при першому запуску.

### 3. Перший збір

Окремим терміналом:

```bash
cd server
npm run collect
```

Триває 5–10 хвилин: близько 30 запитів, між ними пауза, щоб Google не обмежив.
Далі збір іде сам кожні 30 хвилин.

### 4. Інтерфейс

```bash
cd web
npm install
npm run dev
```

Відкрити http://localhost:5173

## Як читати цифри

**Зростання** — наскільки більше стали шукати за тиждень проти попереднього.
Понад 100% підсвічується як різкий сплеск.

**Оцінка** — від 0 до 100, зважена сума трьох складових:
швидкість (50%), обсяг попиту (30%), довіра до сигналу (20%).
Саме за нею впорядковано список.

**Швидкість** — темп зростання зараз.
**Обсяг** — наскільки велика тема взагалі.
**Довіра** — чи підтверджують сигнал обидва джерела. Різкі стрибки понад 400%
знижують довіру: частіше це шум, ніж тренд.

## Налаштування під себе

Список запитів, категорії й вікові групи — у `server/src/taxonomy.js`.
Додавай і прибирай вільно, наступний збір підхопить зміни.

Пороги оцінки — у `server/src/scoring.js`. Якщо здається, що система
переоцінює дрібні сплески, підкрути там коефіцієнти.

## Розгортання

**Сервер** — Render: New Web Service, корінь `server`, команда `npm start`,
змінні з `.env` додати в Environment.

**Інтерфейс** — Vercel: корінь `web`, змінна `VITE_API_URL` з адресою сервера на Render.

## Важливе про надійність

`google-trends-api` — неофіційна бібліотека. Google інколи віддає HTML
замість даних, коли вважає запити підозрілими. Код це відловлює й пропускає
такий запит, а не падає. Якщо в журналі збору систематично багато пропусків —
збільш паузу між запитами в `collect.js` (зараз 1200 мс).

YouTube API має добову квоту 10 000 одиниць. Один пошук коштує 100,
тому близько 30 запитів на цикл — це ~3000 на добу при оновленні раз на 30 хвилин.
Якщо додаси багато нових запитів у `taxonomy.js`, квота може закінчитись —
тоді або зменш частоту збору, або скороти список.
