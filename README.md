# Радар товарних трендів

Збирає сигнали з Google Trends і YouTube, рахує, що росте, і показує список.
Усі файли лежать в одному рівні — так їх можна завантажити в GitHub з телефона.

## Файли

```
package.json      залежності й команди
server.js         API + віддача інтерфейсу + крон
db.js             підключення до бази
schema.sql        таблиці
collect.js        збір трендів
googleTrends.js   джерело: Google Trends
youtube.js        джерело: YouTube
scoring.js        оцінка трендів
taxonomy.js       категорії, вікові групи, запити
index.html        сторінка
main.jsx          точка входу інтерфейсу
App.jsx           сам інтерфейс
styles.css        стилі
vite.config.js    збірка інтерфейсу
nixpacks.toml     як Railway має збирати проєкт
.gitignore
```

## Завантаження в GitHub

Файли завантажуй **як є, в корінь репозиторію**. Папок не треба.

Один момент: `.css` і `.toml` телефон інколи конвертує при завантаженні.
Якщо `styles.css` перетворився на `styles.pdf` — видали його й створи вручну:
Add file → Create new file → назва `styles.css` → вставити вміст → Commit.
Те саме з `nixpacks.toml`.

## Railway

1. New Project → Deploy from GitHub repo
2. Root Directory **не чіпати** — файли в корені
3. Variables → Raw Editor → вставити:

```
DATABASE_URL=рядок_підключення_з_neon
YOUTUBE_API_KEY=ключ
TRENDS_GEO=UA
COLLECT_CRON=*/30 * * * *
```

4. Settings → Networking → Generate Domain

Vercel не потрібен — сервер віддає інтерфейс сам.

## Що буде після запуску

Схема бази створиться автоматично. Якщо трендів у базі ще немає,
збір почнеться одразу після старту — це 5–10 хвилин. Далі кожні 30 хвилин.

Поки збір іде, сторінка покаже, що порожньо. Онови її через кілька хвилин.

## Як читати цифри

**Зростання** — наскільки більше стали шукати за тиждень проти попереднього.
Понад 100% підсвічується як різкий сплеск.

**Оцінка** (0–100) — зважена сума: швидкість 50%, обсяг попиту 30%, довіра 20%.
За нею впорядковано список.

**Довіра** знижується при стрибках понад 400% — частіше це шум, ніж тренд.

## Налаштування

Запити, категорії й вікові групи — у `taxonomy.js`. Пороги оцінки — у `scoring.js`.
Правиш прямо в GitHub, Railway перезбереться сам.

## Обмеження, про які варто знати

`google-trends-api` неофіційна. Google інколи віддає HTML замість даних —
код це переживає й пропускає запит, але частина тем може не оновитись.
Якщо пропусків систематично багато, збільш паузу в `collect.js` (зараз 1200 мс).

YouTube API: 10 000 одиниць на добу, один пошук коштує 100. Близько 30 запитів
кожні 30 хвилин дають ~3000 на добу. Якщо сильно розширити список у `taxonomy.js`,
квота закінчиться — тоді зменш частоту або скороти список.
